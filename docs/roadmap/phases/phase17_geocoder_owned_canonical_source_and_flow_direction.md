# Phase 17 - Geocoder-Owned Canonical Source And Left-To-Right Flow Fix

This phase extends phase 16.

If phase 17 conflicts with previous canonical-seed source ownership, phase 17 governs ownership and processing direction.

## Objective

Fix architecture ownership and flow direction so geocoder no longer depends on analytics-owned artifacts.

Primary outcomes:

- canonical source ingestion is owned by geocoder
- geocode stage runs canonical prep inside geocoder boundary
- analytics consumes canonical outputs as downstream reader only
- pipeline direction remains strictly left-to-right: `crawl -> extract -> geocode -> analytics -> export`

## Problem Statement

Current implementation has a backward dependency:

- geocoder canonical autoseed reads `services/analytics/assets/admin_boundaries_source.geojson`
- that file is generated by analytics scripts

This creates `geocoder <- analytics` coupling, violating service ownership and stage direction.

## Target Architecture

- geocoder owns:
  - canonical source bootstrap/build scripts
  - canonical dictionary import/refresh
  - canonical tables write path
- analytics owns:
  - geometry assets and BI projections
  - read-only consumption of canonical/geocode outputs

### Flow Direction

- geocode stage internal sequence:
  1. optional `canonical_source_refresh` (geocoder-owned)
  2. optional `canonical_dictionary_refresh`
  3. mention normalization
  4. geocoding/linking
- analytics stage must not produce inputs required by geocoder stage

## Data Contract For Geocoder-Owned Seed Source

Seed source file is GeoJSON FeatureCollection with features carrying:

- required:
  - `location_rank` in (`country`, `admin_region`, `continent`, `ocean`)
  - `location_name`
- recommended:
  - `canonical_id`
  - `safe_aliases` / `aliases`
  - `unsafe_aliases`
  - `osm_type`, `osm_id`
  - `country_name` for admin-region linkage

Canonical dictionary derivation rules must be deterministic:

- canonical_name <- `location_name`
- exact alias includes canonical_name
- language variants from safe aliases
- unsafe aliases tagged `unsafe_parent_ref`
- canonical_id from source if present; else stable fallback `seed:<rank>:<normalized_name>`
